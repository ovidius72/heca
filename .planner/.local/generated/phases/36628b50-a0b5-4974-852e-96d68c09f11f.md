## Answered (2026-07-30, F003/P085/T358)

The Nerd Font the app uses for glyphs is the one it **already ships**: `heca-renderer/assets/MapleMonoNormal-NF-Regular.ttf` (+ the Bold face), embedded as the default terminal face long before this phase. ### 📋 00a749da-995d-4012-8ab4-787b5f330987 — T090 — Build NfIcon widget with NfGlyph enum

Status: 📋 `planned`

Widget icon con enum di glyph semanticamente nominati.

## Partially landed early, in F003/P085/T358 (2026-07-30)

The command palette's keycaps needed key glyphs, and neither existing face could give them: Phosphor has **no keyboard glyphs at all**, and the UI face (Geist Mono) has no `⌃ ⌥ ⌘ ⎋ ⇞ ⇟`. So the core of this task was built there:

- **`FontRole::NerdFont`** (`heca-grid-ui/src/scene.rs`) — a third role beside `Text`/`Icon`. The renderer maps it to `font::NERD_FONT_FAMILY` in `heca-renderer/src/scene.rs`, riding the per-run family override the terminal path already had, so `text.rs` needed no new plumbing.
- **`NfGlyph` + `NfIcon`** (`heca-grid-ui/src/widgets/nf_icon.rs`) — single-layer (a Nerd Font glyph is one codepoint, not a duotone pair), same color-inheritance contract as `Icon`.
- **`PaintCx::nf_icon`**, and `paint_keycap_nf` / `KeyCap::Nf` so a keycap can draw one.
- **Showcase gallery** (`NfGlyph::ALL` with name + codepoint) and a `docs/widgets.md` § NfIcon.

**No second font was embedded** (see T098): the app already ships **Maple Mono Normal NF** as the terminal face — a real Nerd Font, loaded unconditionally at renderer init and addressed by family name, so a user's own terminal font cannot take the glyphs away from the UI.

### What is left for this task

`NfGlyph` currently covers **the keyboard set only** — Shift, Control, Option, Command, CapsLock, Enter, Escape, Tab, Space, Backspace, ArrowUp/Down/Left/Right. T103 (wire NfIcon into the program catalog) needs the **program/devicon** glyphs, which are not in the enum yet. Adding one = variant + `codepoint()` + `name()` + `ALL`.

### The trap for whoever adds glyphs

`heca-renderer/tests/font_coverage.rs` proves every codepoint is **in** the embedded font (a missing one would render as tofu, which no other test can see). It **cannot** prove a name matches its picture: the font names its glyphs `uniF0636`. The five `nf-md-apple_keyboard_*` codepoints were read off the Material block's alphabetical order (caps, command, control, option, shift = F0632..F0636) and **must be confirmed by eye in the showcase gallery** — same caveat `Glyph::CaretLeft` carries. If one is off by one it is a one-character fix.

### 📋 adce30df-62ce-4a23-900a-097fec336df5 — T098 — Embed Nerd Font glyph ranges

Status: 📋 `planned`

Embedding dei range di glyph usati.

## Reconsidered (2026-07-30, F003/P085/T358)

**Nothing new needs embedding today.** The app already ships a full Nerd Font — Maple Mono Normal NF, the default terminal face — loaded unconditionally at renderer init (`heca-renderer/src/text.rs`) and now addressed by family name for chrome glyphs too (`font::NERD_FONT_FAMILY`, `FontRole::NerdFont`). Every glyph `NfGlyph` names was verified present in its `cmap`.

So this task is really about **subsetting**, not embedding: the face carries ~12k codepoints and the app uses a handful outside the terminal. That is a binary-size question to answer on its own evidence (how much of it the terminal itself needs — a terminal genuinely wants the whole NF range, which may leave nothing to strip), not a prerequisite for `NfIcon`.

Whoever picks this up: measure first, and check whether subsetting the terminal face breaks a user's powerline/devicon prompt before touching anything.
