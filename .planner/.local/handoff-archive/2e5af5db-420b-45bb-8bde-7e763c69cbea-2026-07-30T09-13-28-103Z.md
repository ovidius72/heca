## The rules this phase settled — do not re-litigate

- **The ownership test** (now in `Provider::actions`'s doc): *remove the component; does the action
  still make sense?* Yes → the app's, the component **binds** it. No → the component's, it
  **declares** it. This is why `create_workspace`, `zoom_column` and `workspace_next` are not
  declared, and it separates two actions one name can hide (*switch the active workspace* is the
  app's; *move my cursor to the next workspace row* would be the component's, and does not exist).
- **A container's context menu is the component's**, never the host's. The host seeds `pane` only.
- **Paths and action ids are namespaced by component**, never by location — `workspaces.pane`, not
  `sidebar.pane`. Same defect `SidebarTree` and `sidebar_*` had.
- **Keys are flat at the container level**; the component decides meaning from the row the cursor is
  on. Binding names are short (`cursor_up`); the action id is `<component>.<name>`.
- **Policy is per action, not per component.** A shared default in one closure silently made eleven
  actions `Global`. The cursor is chrome state (`Global`); every mutation is `TiledOnly`.
- **Policy is not config-assignable** (proposed, analysed, rejected). It is a correctness property the
  action's author knows and the user does not. If a real case appears, the defensible form is
  **deny-only**: config may restrict further, never loosen, and a loosening attempt is reported.
- **The cursor is the component's to say.** The host keeps one per mount, but a component whose model
  has a single cursor must light the same row in every seating; `mirror_cursor_to_siblings` follows
  the model rather than asserting against it.

## Traps that cost time — worth reading before touching keys or wording

- **A component's short binding name that matches a built-in resolves to the built-in.** Config is
  built before providers register, so nothing can know better. It silently made
  `workspaces.create_workspace` dead, and left `delete_column` bound to a built-in needing args a key
  cannot supply — the startup report caught the second. Hence `delete_selected_column`.
- **`WorkspacesContainerState::tree()` is a `RefCell`.** End the borrow before any call that reaches
  back into the store, or it panics at runtime instead of failing to compile.
- **`AppState` cannot be constructed in a test** — one site, `heca/src/app/startup.rs`, needs a
  window. Nothing at the `handle_*` level is unit-testable. Put assertions on the component through
  `ProviderCx`, or extract a pure function (`placement_for`, `scope_at`, `confirm_title_for` were all
  split out for exactly this), and expect the user to drive the rest in the app.
- **User-facing wording has four independent sources** — `ActionDescriptor.label`,
  `ConfirmSpec.buttons[].label`, `confirm_title`, and hand-written `DropdownItem` labels. Changing a
  verb means touching all four; T370 needed three passes to learn that, each time found by the user
  reading the app.
- **Deleting a mode is not mechanical.** `InputMode::SidebarNav` looked inert; it still had a *writer*
  on the prefix path, and removing the mode killed the only caller of a fix made minutes earlier.
  Delete the variant and let the compiler find everything.
- **Do not put `rg` after a heredoc in one shell command.** With no path argument it reads stdin and
  hangs forever; two processes sat for five hours this session.
- Repo rule: **never run `cargo fmt`**. Rust-skill review → clippy → commit, and **wait for the
  user's approval before committing**.
