## ⭐ READ FIRST — the layout API changed on 2026-09-16
**`docs/layout.md`** is the record and the reference: which container to reach for, how to say a size, a space, a track and an alignment, and the traps with the defect each one cost. `AGENTS.md` § 1 points at it. **`P052(F004)`'s phase description** carries the same summary for anyone entering that phase, and four tasks there reference it: **T350** (share idiom — its item 1 landed today), **T517** (new: parts found by child position), **P094(F011)/T450** (the pane's header/content template), **P087(F011)/T469** (CommandPalette composes).

What is true now, all uncommitted:
- **Every value reads its CSS spelling**, through one parser shared with the wire: `Track` (`"auto"`, `"1fr"`, `"200px"`, `"repeat(3, 1fr)"`, `"min-content"`), and `Justify` / `Align` / `Direction` (`"space-between"`, hyphen or underscore). ~100 hand-written enum variants swept out of real code.
- **The grid is CSS-shaped.** `.template_row(..)` / `.template_column(..)` / `.template_area(..)` on the container; `.child(one_or_many)` auto-places as in HTML. **Placement is the CHILD's property** — `.column("1 / -1")`, `.row(2)`, `.column_span(Span::All)`, `.area("title")`. `.cell(child, …)` and `.row(child)` are **gone** from the grid. Names and `1 / -1` resolve during **layout**, against whichever grid holds the child, via `Component::grid_template`.
- **One door for children.** `.child(x)` and `.child([a, b])` are the same builder, on every widget and on `ViewNode`. The `child` / `children` pair is deleted.
- **`flex-basis` exists** — `.basis(..)`. A share is `.grow(w).basis(0.0).shrink(1.0)`, real CSS `flex: 1 1 0`; `expose::share_v` uses it.
- `Icon` and `NfIcon` implement `LayoutExt`. `CardGrid`, `Visibility`, `KeyHintGroup` still implement no builder trait — untouched.
