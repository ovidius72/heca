## Slice 2b design (approved by the orchestrator, 2026-10-01)
Goal: a Terminal inside an overlay or dock works (AGENTS § 0d), because terminals draw in scene order. Today terminals are blitted in `render.rs` Pass 2 (tiled) and a per-float step, BEFORE the scene holding their pane tree is flushed; a terminal in the chrome scene would be covered by its dock's background.
1. **New band in the scene, scoped to its own flush** (NOT the global overlay segments, which sit above modals). Name it for what it does: `PaintCx::outline` / `after_children` (CSS outline). `Scene` gets an `outline` vec + tracking of open base clips; begin replays the open clips into the band and end pops them, so segments are self-contained. `base_layer()` returns base commands then outline, so the host's base pass draws them last. Inside an overlay or another outline it paints inline (no jump above a modal). Test with a clip-stack scene test, including nested panes. Document in docs/widgets.md (Scene/PaintCx).
2. **Pane** (`heca-grid-ui/src/widgets/pane.rs` `paint`): fill first (base), children, then border + glow via the outline band (today one `cx.rect(fill, border, glow)`; split into a fill-only rect and a transparent-fill border+glow rect). Result in the column scene: fills/headers/terminals in scene order, then ALL panes' borders and glows on top = what Antonio sees today (active glow bleeds over the neighbour's terminal).
3. **Host flush splits at each `HostDraw::Surface` only**: flush base so far, blit that terminal (reuse `blit_retained_terminal_layer`, `queue_terminal_dynamic_overlays`; stencil/scissor of the scene that holds it: tiled mask, the float's own mask, none for dock/overlay), flush its cursor/selection overlays, continue. A scene with no surfaces stays one pass. The two hand loops in render.rs (Pass 2, per-float) go away. Retained textures, damage, row-range merge untouched. Surface id -> pane via `state.terminals` / `Terminal::id()`.
4. **Frame-time instrumentation**: documented debug env var, off by default, logs `render_frame` CPU time averaged over 120 frames plus pass count; take numbers at 1/4/8 panes (+1 floating) before and after; say plainly GPU time is unmeasured.
5. **API gap**: `Terminal::new("name")` must be reachable from an outside crate with the command seam from the build context (like the T520 doors). Today `Terminal` is `pub(crate)`, built by `chrome/terminal::view_of(state, pane)`. A non-pane terminal needs a name-keyed process in the store (name is only a property) and a pending-request path from BuildCx (which has no AppState), drained by the host like `drain_pending_menus`. Then `heca/examples/extend_heca.rs` adds a dock/layer holding a Terminal; Antonio checks 2b by running `cargo run -p heca --example extend_heca`. NO temporary debug action (orchestrator's decision).
Eye check for 2b: active-pane border and glow over terminals, neighbouring panes, a floating pane over tiled ones, frost, transparency, rounded corners, the exposé, then the example dock's terminal.
