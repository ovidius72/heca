## Blockers and risks
**Findings from reading the focus code (do not redo):**
- Click-to-focus exists once: `FocusManager::dispatch_inner/focus_at/focus_at_trapped` (heca-grid-ui/src/focus.rs:249-304); copies: `Overlay::focus_at_trapped` (widgets/overlay/mod.rs:673), `Dialog` (dialog.rs:495) and the `Component::focus_at_trapped` trait method (component.rs:1081). The app's `component::dispatch(window_root, ev)` does NO click-to-focus: today a click on a Button/Input/Row in a dock focuses nothing.
- Focusable widgets (`base.focusable = true`): Toggle, Toast, Tabs, Select, Row, RailCell, Item, Input, IconButton, Choice, Checkbox, CardGrid, Button, BadgeButton. `Row`'s cursor look is `nav || focused_by_keyboard()` (focused AND focus_visible), and a click gives mouse focus (focus_visible=false), so a click does not look like the dock cursor.
- Host-bound `focused` (a second meaning): Overlay (new, open_when, follow_open), ContextMenu, CommandPalette set `base.focused = open`; ScrollRegion.keyboard_target and FocusScope.focus bind it to the chrome store's focused_container flag. master wants ONE meaning: `Base::focused` written only by one `focus()/blur()` door, the click rule and the host using the same door (like element.focus()). All five can move by an edge check on their signal inside the widget (in `tick` and at the top of the keyboard walk, so no frame passes between opening and the first key); the writers of those signals hold no tree, so the door must be "observe, then focus()", never "the store calls focus". No `focus_bound` marker.
- Pane/sidebar risk: keys go to the tree only when the focused SURFACE is a Layer or a Dock, never for the Panes surface (pane keys go to the pane's backend by hand), so a clicked header button holding focus cannot take typing from its pane. In a dock, surface keymaps run first and the tree gets only unclaimed keys; test per claimed key (j/k/Enter stay with the surface). There is no headless AppState: prove it with a pure `delivers_to_tree(surface)` unit test per surface kind.
- The dock branch in `heca/src/app/input.rs` swallows unclaimed keys today; keep prefix sequences and dock bindings working.
- Eye checks are batched by master for Antonio; nothing here is verified by eye yet.
