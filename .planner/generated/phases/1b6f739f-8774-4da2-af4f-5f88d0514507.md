The library's missing text capability, recorded as an open gap in AGENTS for months and worked around four separate times.

Two small widget capabilities that four call sites have been hand-rolling because the library never had them.

## Why it exists

AGENTS.md records it plainly: *"truncation/ellipsis + wrapping (a long label overflows its box today)"* — in a **prose list of open gaps, never filed as a task**, which is precisely how it stayed open while four hand-written truncations grew around it:

- `heca/src/chrome/mod.rs:286` `truncate_path_left` (start-ellipsis, keeps the tail — paths);
- `heca/src/chrome/mod.rs:391` the pane info bar's overflow budget, measuring with its own `char_w = font * 0.6` (a hand-copy of `MONO_ADVANCE_RATIO`);
- `heca/src/chrome/mod.rs:1428` `truncate_sidebar_git_branch` (a fixed char cap);
- the command palette's `fit()` (F003/P085/T358).

`heca/src/providers/workspaces/mod.rs:1231` even carries a comment deferring to *"when label truncation/wrapping is settled"*.

## What already exists — nothing new is needed underneath

- `Label::remeasure` sizes itself `chars × font × MONO_ADVANCE_RATIO` wide and `font × MONO_LINE_RATIO` tall, and `paint` draws into `base.bounds`. Fitting to the box is therefore a paint-time cut against the same measure the layout used.
- `Layout::flex_shrink` and `min_size` exist (taffy 0.7), and `style.rs:423` documents `Px(0.0)` as the way to let a node go below its content size — so "may be given less than its natural width" needs no engine change.
- `Item` **already composes**: its label is a real `Label` child (index 1) between two slot `Flex`es, and its own doc says the label "can be swapped or extended without touching `Item::paint`". The second line is another `Label`, never text drawn by `Item`.

## Scope

`Label` gains truncation (End and Start ellipsis) and `Item` gains a description line. **Both stay in `heca-grid-ui`** — a widget is what can be built there, and these can. The four app-side copies are deleted by F011/P089/T376, which is blocked on this.

## Behaviors to preserve

Existing labels are unaffected unless they opt in — a `Label` with no truncation set keeps its current natural size and overflow behaviour, or every layout in the app shifts at once. `Item`'s row height only changes when a description is present. Measure stays the shared `MONO_ADVANCE_RATIO` (a Phase-A approximation until cosmic-text shaping lands — centralising it here is what makes that a one-place fix later).

### 🚧 4845ea12-be54-4cae-9e0c-059252d2b65f — T379 — Label fits its box — .truncate(End | Start), measured once

Status: 🚧 `in-progress`

The capability four call sites have been hand-writing.

## What exists

`heca-grid-ui/src/widgets/label.rs`:
- `remeasure()` sets `width = chars × font × MONO_ADVANCE_RATIO`, `height = font × MONO_LINE_RATIO` — the label's **natural** size.
- `paint()` draws `self.text` into `self.base.bounds` with the resolved colour/align/style, then draws decorations over the **run** (`run_rect()`), not the box.
- Builders today: `align`, `color`, `bold`, `italic`, `underline`, `strikethrough`, `font_size`, `font_scale`, `text_signal`.

`heca-grid-ui/src/style.rs`: `Layout::flex_shrink` (`None` ⇒ `0.0`) and `min_size`, with `Px(0.0)` documented at :423 as the way to allow shrinking below content size.

## What to build

`Label::truncate(Ellipsis)` where `Ellipsis` is `End` (labels, descriptions — cut the tail) or `Start` (paths, git branches — keep the tail, cut the head). Two behaviours together, and the second is the one that makes it work:

1. **Layout**: a truncating label declares itself shrinkable — `flex_shrink = 1.0` and `min_size.width = Px(0.0)` — so the engine may hand it less than its natural width. Without this it keeps its full width and simply overflows, and the paint-time cut never triggers. This is the same trap as F003/P067's `flex_grow` lesson: a size that cannot shrink does not participate.
2. **Paint**: fit the text to `bounds.size.w` using the *same* `MONO_ADVANCE_RATIO` cell the measure used, cutting from the end or the start and appending/prepending `…`. Cells `0` ⇒ nothing, `1` ⇒ `…` alone.

`run_rect()` must follow the **drawn** text, or an underline/strikethrough would span the untruncated width.

## Edge cases

- Not truncating (the default) leaves `remeasure`, layout and paint exactly as they are — no existing label may move.
- A signal-driven text that changes still re-measures; the cut is computed at paint from the current bounds, so it follows a resize with no rebuild.
- Multi-byte text: count **chars**, never bytes (`truncate_path_left` already does).

## Test (assert the drawn thing)

Paint into a `Scene` and read the `DrawCommand::Text`: wide box ⇒ the full string; narrow box ⇒ a shorter string ending (or starting) in `…`; `Start` keeps the tail — `…/deep/path` — and `End` keeps the head. A test asserting only a flag is the F004 lesson repeated (a `grow` flag once passed while the layout was visibly broken); assert the text and the run rect.

**Checklist:**
- [ ] Ellipsis { End, Start } + Label::truncate(mode) builder
- [ ] truncating label declares flex_shrink + min_size.width = Px(0) so the engine can give it less
- [ ] paint fits to bounds.size.w on the MONO_ADVANCE_RATIO cell; 0 cells ⇒ nothing, 1 ⇒ …
- [ ] run_rect follows the DRAWN text so decorations do not span the untruncated width
- [ ] default (no truncate) leaves measure/layout/paint byte-identical
- [ ] scene test: wide vs narrow, End keeps the head, Start keeps the tail, chars not bytes
- [ ] docs/widgets.md § Label documents it; the AGENTS open-gap line is struck

## What exists

`heca-grid-ui/src/widgets/item.rs` builds three children in `Item::new` (:117-122) and names their indices:

```
const LEADING: usize = 0;   // Flex::empty() slot
// 1 = the label — `Label::new(label).align(TextAlign::Start).grow(1.0)`
const TRAILING: usize = 2;  // Flex::empty() slot
```

with the doc: *"The label is a real `Label` child (not text drawn by `Item`), so the row is composed like every other widget: the engine lays the three out, each paints itself, and the label can be swapped or extended **without touching `Item::paint`**."* That is the seam this task uses — the description is another `Label`, and `Item::paint` is not touched.

Constants that will need to follow the row's height: `ROW_H` (38.0), `FONT_SIZE` (15.0), the selection pill inset `SEL_INSET`, the active bar `ACTIVE_BAR_FRAC`.

## What to build

`Item::description(text)`: the label child becomes a `Flex::column` of the title `Label` and a muted description `Label` (theme `muted`, smaller `font_scale`), and the row grows to two lines **only when a description is set**. Slots stay vertically centred against the whole row; the active bar and the selection pill scale with the row rather than assuming `ROW_H`.

Pair it with `Label::truncate` (T379) so a long description cuts instead of overflowing — the palette rows are the first consumer, via F011.

## Edge cases

- **No description ⇒ nothing changes**: same height, same paint, same measure. Every existing `Item` in the sidebar, menus and `Select` options must be pixel-identical.
- `label_signal()` keeps addressing the **title**; a description signal is separate if one is needed later (not now — no consumer).
- The description must not steal the row's activation: it is a plain child, and `on_activate` stays the row's.

### 📋 5408f2d8-b2fa-47dd-867e-e4d5cbf1964d — T382 — Label wraps — height from width, the other half of the gap

Status: 📋 `planned`

The second half of AGENTS.md's open gap (*"truncation/ellipsis **+ wrapping**"*). `Label::truncate` (T379) closed the first half; this is the harder one.

## Why it is harder than truncation

Truncation is a **paint-time** cut against the box the engine already gave the label — the measure never changes. Wrapping changes the measure itself: a wrapped label's **height depends on its resolved width**, which a fixed `Length::Px` measure cannot express.

`heca-grid-ui/src/widgets/label.rs::remeasure` today sets:

```
width  = chars × font × MONO_ADVANCE_RATIO      // one line, natural width
height = font × MONO_LINE_RATIO                 // exactly one line
```

Taffy (0.7, `heca-grid-ui/src/layout.rs`) supports content-driven sizing through a **measure function** on leaf nodes — that path is what this task has to reach; the engine does not use it for labels today. Check whether `LayoutEngine` already wires one for any widget before adding a second mechanism.

## What to build

`Label::wrap(bool)` (or `Wrap::{None, Word}`) — mutually exclusive with `truncate`, since a label either cuts or reflows:
- break on **word** boundaries, falling back to a hard break for a word longer than the line;
- height = `lines × font × MONO_LINE_RATIO`, computed from the width the engine offers;
- the run rect / decorations follow the **last** line, or span each line, whichever the existing `run_rect` contract can honour — decide and document it.

## The consumer that asked for it (2026-07-30)

The command palette wraps **the selected row's description only**, and the list **reflows** — rows below shift down as the cursor moves, CSS-style, which the maintainer chose explicitly over a fixed two-line allowance. So the palette needs per-row heights that change with selection; row geometry there is already per-row (`row_rects`), so the reflow follows from the label's height being honest.

## Behaviors to preserve

A label that sets neither `wrap` nor `truncate` keeps today's single-line measure exactly — every existing layout in the app depends on it. Wrapping must not silently change the natural width either: a wrapped label still asks for its full width and only *accepts* less.

## Test

Assert the drawn lines, not a flag: the same text in a wide box paints one text run, in a narrow box paints N runs at increasing y, and the label's measured height is N line-heights. A long unbreakable word still fits (hard break) rather than overflowing.

**Checklist:**
- [ ] check whether LayoutEngine already wires a taffy measure fn for any widget — do not add a second mechanism
- [ ] Label::wrap — word breaks, hard break for an over-long word, height = lines × line height from the OFFERED width
- [ ] mutually exclusive with truncate; a label with neither keeps today's single-line measure byte-identical
- [ ] run_rect / decorations behaviour with multiple lines decided and documented
- [ ] palette: selected row's description wraps and the list REFLOWS (rows below shift) — the requested behaviour
- [ ] test asserts N text runs at increasing y and the measured height, not a flag
