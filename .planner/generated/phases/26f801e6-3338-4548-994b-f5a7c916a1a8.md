# 26f801e6-3338-4548-994b-f5a7c916a1a8 — P089 — The pane header and the info bar come out of chrome/mod.rs

**Status:** 📋 `planned`
**Created:** 2026-07-30T13:27:59.996Z
**Updated:** 2026-07-30T13:38:46.383Z

Extract the header (title + action buttons) and the segment bar (icons + text + overflow) into components, deleting the hand-rolled measure and truncation with them.

The two biggest compositions inside `heca/src/chrome/mod.rs` (4960 lines, host logic and UI in one file), and the ones carrying the hand-rolled text measuring this feature exists to end.

## What exists

- `build_pane_header()` :782 — title + the configured `PaneAction` buttons, each wired by hand (tooltip + hint + intent). `pane_action_spec()` :549 maps a `PaneAction` to (glyph, `WmAction`, label, focus-first) and stays the source of truth for what a button *is*.
- `build_pane_info_bar()` :323 — icon+text segments (location, app name, git branch/status) with a **hand-rolled overflow budget** at :391: it measures with its own `char_w = font * 0.6` — a copy of `MONO_ADVANCE_RATIO` — computes the overflow in characters and left-ellipsises one designated segment through `truncate_path_left()` :286.
- `build_pane_viewport_widgets()` :906 — the per-pane scrollbar + badge.
- The same truncation exists a third and fourth time: `truncate_sidebar_git_branch()` :1428 (a fixed `SIDEBAR_GIT_BRANCH_MAX_CHARS` cap) and, as of F003/P085/T358, inside the command palette.

## Blocked on the library owning text

`Label` has **no truncation** — recorded as an open gap in AGENTS.md and never filed as a task, which is exactly how four hand-rolled copies came to exist. File and land `Label` truncation (`End` / `Start` ellipsis, measured once) in **F004** first; then the info bar's budget becomes "give each segment its box and let the labels fit", and `truncate_path_left` / `truncate_sidebar_git_branch` / the palette's copy all delete.

## What to build

- A **segment bar** component: an ordered list of (glyph, text) segments, one of them nominated as the shrinkable one, laid out by `Flex` with the labels doing their own fitting. No character arithmetic at the call site.
- A **pane header** component composing it with the action buttons from P087's action-button component.
- Both consumed by `chrome/mod.rs` in the same task that extracts them; the old functions go.

## Behaviors to preserve

Pixel-identical bars and headers; the header rebuild cadence (`chrome_signature` / the width bucketing at :748 that keeps a resize from thrashing the rebuild) unchanged; per-pane header trees keep their own hint-id ranges and `remove_range` on rebuild; tooltips keep resolving through the action **name** so a rebind still updates them.

## What exists

`heca/src/chrome/mod.rs`:

**`Label` must own truncation first** (F004 — file it; AGENTS.md records it as an open gap and it was never a task, which is exactly how four copies happened). Once a `Label` fits itself to its box, the bar becomes "give each segment its box, nominate the shrinkable one" and the arithmetic goes.

## What to build

A **segment bar** component: an ordered list of `(glyph, text)` segments with one nominated as shrinkable, laid out by `Flex`, each label fitting itself. No character counting at the call site, no `char_w`, no `truncate_path_left`.
