═══ THE HEADLINE DECISION ═══
The collapsed icon rail is DROPPED for now. A region is **Expanded** or **Hidden**.
`RegionMode::CollapsedRail` stays in the enum (heca-grid-ui/src/widgets/chrome_region.rs), unused;
no region enters it and nothing renders it. `RailCell` stays a library widget, mounted nowhere.

═══ THE THREE LAYERS — KEEP THEM SEPARATE, MOST CONFUSION COMES FROM BLURRING THEM ═══
1. SIDEBAR SHELL (the region host) — a generic, domain-neutral `ChromeRegion`: framing, background,
   border, width, visibility, display mode. It knows NOTHING about workspaces, Docker or agents.
   One shell per region.
2. PROVIDER (the hosted widget) — what is mounted inside: WorkspacesContainer today; Docker, AI
   agents, git, notes, plugin-defined ones later. A region may host several and shows one at a time.
3. A PROVIDER'S CONTENT — groups and items, nested to any depth. For WorkspacesContainer:
   workspaces (groups) → columns → panes (items). Columns are structural; they are not rows.

═══ RULE THAT PREVENTS THE BUG CLASS WE HIT: MODE IS STATE, NEVER WIDTH ═══
The renderer branches on `RegionMode`, never on a width threshold. Every input that changes the
mode — the toggle button, a keybinding, RPC, and drag-resize — WRITES the mode state; the renderer
only READS it. Dragging the edge below the minimum DISPATCHES the action that sets Hidden; it does
not make the renderer inspect a width. Mode = which form, width = how wide when Expanded. One
source of truth each is what keeps mouse, keyboard and RPC in agreement.

═══ §3 — THE RENDER-PER-MODE CONTRACT (generic for EVERY Provider) ═══
WRITE ONCE — the author never writes two trees. A Provider describes its content once as a semantic
tree of Groups and Items, each node carrying its meaning a single time:

    Item {
      icon:    <glyph>,          // e.g. the program icon
      label:   <text>,           // e.g. the pane name
      status:  Idle | Running | Success | Error,
      intent:  <action>,         // e.g. FocusPane
      actions: [ ... ],          // extra affordances (git, exit, buttons) — expanded only
    }
    Group {                      // e.g. a workspace
      identity:  icon | name | number,
      collapsed: bool,
      children:  [ Group | Item ]   // nested to any depth
    }

DISPLAY MODE IS THE HOST'S CONCERN, NOT THE AUTHOR'S. The host renders that one tree for the
region's current mode:
- Expanded → nested frames + full rows: Group → `DockFrame`, Item → `Row`, with all extras.
- Collapsed → a `RailCell` per node, recursively: a Group cell, then (if expanded) its children
  beneath it; an Item → a `RailCell`. Expanded-only extras (git, exit, action buttons) are omitted.

The mode-awareness lives in exactly ONE place: `realize()`. Not duplicated in the author's code,
not duplicated across widgets. Double authoring is exactly what this rejects — it would fall on
every plugin too.

GROUP COLLAPSE IS GENERIC. "A group shows or hides its children" is one host behaviour available to
every Provider. A workspace showing or hiding its panes is just that behaviour applied to
WorkspacesContainer. Nothing about it is workspace-specific.

TWO COLLAPSE FLAVOURS, declared per Provider, applied by the host:
- LIST provider (workspaces and similar) — ENUMERATES: one cell per item when collapsed.
- TOOL provider (a Docker panel, say) — FOLDS: the whole Provider becomes a single icon.

INTERACTION IS GENERIC. Status→colour, the letter/KeyHint picker over cells, active and cursor
states, and right-click menus are HOST capabilities applied to any Provider's items. The Provider
supplies only, per item: its intent, its status, and its context-menu entries.

═══ §4 — THE COLLAPSED RAIL VISUAL SPEC (the reference implementation of the generic renderer) ═══
When built it MUST be the generic host renderer above — never a workspace-only, hand-drawn rail.

STRUCTURE: a flat vertical list (inside a `ScrollRegion` for overflow) of `RailCell`s — workspace
cell, then its pane cells when that workspace is expanded, then the next workspace cell. Columns are
not shown as cells; an expanded workspace lists its panes flattened across its columns.

CELL IDENTITY — two config settings, both `[appearance]`, typed snake_case enums, default "icon",
both to be added to config.default.toml and the README:
- `workspace_collapsed_style = "icon" | "name" | "number"` — icon = `Stack` glyph; name = initial
  letter of the workspace name; number = 1-based workspace number.
- `pane_collapsed_style = "icon" | "name" | "number"` — icon = the program icon from the catalog,
  FALLING BACK TO `FolderSimple`; name = initial letter of the pane name; number = pane number.

COLOURS — theme tokens, never literals:
- Workspace cell = accent; the active workspace (holding the focused pane) renders brighter
  (`RailCell.active`).
- Pane cell = status: Idle → muted, Running → accent, Success → success, Error → danger. The
  focused pane renders brighter. Workspace and pane never read the same because the glyphs differ
  (`Stack` vs the pane icon).

CURSOR: the sidebar-nav cursor shows as a distinct hollow outline — add `nav_selected` to
`RailCell`, mirroring `Row` / `MarkerGroup` / `DockFrame`.
CLICKS: a workspace cell toggles its pane list and does NOT switch workspace; a pane cell focuses
that pane.
RIGHT-CLICK: the SAME context menu as the expanded form — reuse the existing menu builders.
KEYHINT: the universal picker stamps letters over the cells (wrap each `RailCell` in `KeyHint`),
fed by the existing pick-candidate signals. Column-target picks are unavailable while collapsed
because columns are not shown — an accepted limitation.

WIDGET WORK REQUIRED (verified NOT built, 2026-07-26): extend `RailCell` to show a short text label
for the name/number styles; add its `nav_selected` state (grep finds 0 hits in rail_cell.rs); and
add `Glyph::Stack` to the icon set (`Glyph::FolderSimple` already exists).
