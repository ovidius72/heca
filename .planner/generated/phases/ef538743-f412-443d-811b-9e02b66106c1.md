### 📋 486740a3-877a-4b33-9c71-48d25f36f16a — T008 — Unify scrollbar behaviour — one shared implementation for every scrollable widget

Status: 📋 `planned`

USER-RAISED 2026-07-24: "scrollbar behavior MUST be controlled and implemented internally to all widgets that are scrollable (maybe a trait) and not reinvented when a scrollbar is needed". I audited the library; the user is right. Recorded here rather than folded into F003/P011/T015 because it touches four widgets and changes all of them visually.

═══ AUDIT (verified 2026-07-24 by grep + reading each file) ═══
FOUR parallel implementations. They do not even agree on the thumb width — that is the proof they were copied, not shared:

| widget | file | thumb w | model | drag | hover | grab lane | track paging |
|---|---|---|---|---|---|---|---|
| ScrollRegion | widgets/scroll_region.rs (~175 scroll refs) | SCROLLBAR_W = **8.0** (L50) | continuous px offset (Signal<f32>) | yes | yes | yes, THUMB_HIT_W 16 (L58) | yes, press-and-hold repeat |
| ScrollBar | widgets/scroll_bar.rs (~49) | THUMB_W = **3.0** (L18) | continuous px (host supplies content/viewport/offset) | yes | yes | no | no |
| Select | widgets/select.rs (~16) | SCROLLBAR_W = **4.0** (L79) | discrete ROW INDEX (`scroll: usize`, `max_scroll()`) | NO — hand-drawn `cx.rect` thumb at L693-709 | no | no | no |
| CommandPalette | widgets/command_palette.rs | **none drawn** | discrete row index (`scroll: usize` L136, `visible_rows()` L251) | — | — | — | — |

KEY FINDINGS:
1. **ScrollRegion does NOT use the ScrollBar widget.** scroll_bar.rs's own module doc says its "visual language intentionally matches ScrollRegion's accent thumb so hosts don't get a second scrollbar style" — i.e. it re-creates the look by hand. That is exactly how 3.0 vs 8.0 vs 4.0 happened.
2. **CommandPalette has no thumb at all** — a long result list gives the user no position feedback. Functional gap, not just style.
3. **Two different scroll MODELS**, which is why they never converged: continuous pixel offset (ScrollRegion/ScrollBar) vs discrete row-window `scroll: usize` (Select/CommandPalette). A shared abstraction must serve both — a row-window widget feeds it row_count × row_height as the content extent.

═══ WHAT TO BUILD ═══
The shared unit is thumb GEOMETRY + interaction derived from `(content_extent, viewport_extent, offset)` → thumb rect, hit lane, drag delta→offset, track-page target, hover/drag brightness. That is already what `ScrollBar` models, so prefer PROMOTING it (or extracting its maths into a `ScrollThumb`/`Scrollable` helper both it and ScrollRegion call) over inventing a fifth thing.
1. Extract the geometry+interaction into one place (free functions or a trait with provided methods — a trait is only worth it if widgets share state shape; the maths is the real duplication).
2. ScrollRegion renders its thumb through it (keeping its grab lane + press-and-hold paging, which are the richest behaviours and should become the shared baseline).
3. Select renders its dropdown thumb through it — and GAINS drag + hover, which it lacks today.
4. CommandPalette gains a real thumb.
5. ONE set of tokens (thumb width, pad, grab lane, min thumb) — today 3.0/4.0/8.0. Theme-driven per the no-hardcoded-style rule; decide whether thumb width becomes a theme token.
6. Docs BOTH audiences + showcase coverage for each converted widget.

═══ CONSTRAINTS / EDGE CASES ═══
- Select's rows are PLACED CHILDREN and its scroll is a row index — do not convert it to px offset as a side effect; feed the shared maths instead.
- ScrollRegion's wheel is children-first (innermost hovered region wins) and hover-gated because Event::Scroll carries no position — preserve.
- Keep the `bounds === drawn === clickable` invariant; ScrollRegion bakes -offset into child bounds.
- A press must be matched by its release or a drag sticks to the cursor (fixed for the overlay path in F003/P011/T015 — Dialog/Overlay now route PointerReleased; make sure the shared path cannot regress it).
- VERIFICATION: visual + interactive for all four widgets — user drives `cargo run -p heca-renderer --example showcase`. Unit tests cover the geometry maths only.
