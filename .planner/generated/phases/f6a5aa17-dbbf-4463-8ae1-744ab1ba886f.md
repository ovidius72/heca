From the 2026-06-17/18 compatibility re-check. The keybinding complaints were mostly fixed by the
registry rewrite; these three remain.

LESSON RECORDED THERE, WORTH KEEPING: one claim ("focus-up jumps workspaces") was tested and proved
FALSE. Verify behaviour by RUNNING it, not by reading a code path.

1. CATALOGUE EVERY ANIMATION, for a future animation overhaul.
   Write down the full set of motions niri animates and how — open, close, move, resize,
   workspace-switch, view-scroll, overview. niri gives each its own spring/easing config and an off
   switch. Then map each to what heca does today: heca appears to use one simple easing for
   everything, with no spring physics, no per-motion config, and no way to turn animations off.
   The deliverable of this task is the catalogue and gap list. The improvement itself is later work.

2. CONFIRM WHETHER ADDING OR REMOVING A COLUMN ACTUALLY RESIZES THE OTHERS.
   heca recomputes all column widths on every layout change — `update_all_column_widths()` runs on
   every mutation in `heca-core/src/layout/scrolling.rs`. niri never resizes existing columns when
   you open a new one. The open question is whether heca's recompute really changes existing widths
   at runtime or just re-derives the same numbers.
   TEST IT LIVE: resize a column, add and remove another, resize the window — does the first column
   keep its size? If it reflows, switch to storing each column's width and recomputing only the
   changed one.
   ⚠️ This blocks mouse divider-resize (F006): it is unverified whether a manual resize persists or
   gets recomputed away, and divider-drag would feel broken either way until this is settled.

3. RE-AUDIT THE COMPAT ITEMS STILL MARKED "UNVERIFIED" in niri-compatibility-review.md:
   prefix-mode timeout · whether modifiers are read from the event or from a cache · sending a
   literal prefix key through to the terminal · the viewport/chrome coordinate math · the
   single-animation model · the column-width double-caching.
   Go through each against current code, run it where behaviour matters, and update the review's
   status table.

REFERENCE: `niri-compatibility-review.md` + `docs/niri-wiki/` — keep both, do NOT delete. The review
itself needs updating to reflect current heca (flagged 2026-06-17).
