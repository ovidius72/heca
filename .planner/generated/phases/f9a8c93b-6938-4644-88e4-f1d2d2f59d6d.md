2. Give `Dialog`'s panel a **font-derived** minimum — the note said **~22em** (i.e. `22 × base font`), so it scales with the theme font instead of being a magic pixel count. Verify against the real dialogs (delete-pane confirm, the rename form).
3. Tests: a `min_width` smaller than the content is a no-op; larger than the content floors the box; it scales with the base font.
4. `docs/widgets.md`: the `Style`/`LayoutExt` tables + the `Dialog` entry.

### 📋 d9527a20-4e5e-4da2-ba02-c795d966d04e — T350 — A proportional share must not be written as a fixed measure

Status: 📋 `planned`

# The problem

To make two containers take half a region each, `with_share` (`heca/src/chrome/mod.rs`) writes:

```rust
layout.flex_grow = grow;
layout.height = heca_grid_ui::Length::Px(0.0);      // ← a FIXED measure
layout.min_height = Some(heca_grid_ui::Length::Px(0.0));
layout.flex_shrink = Some(1.0);
```

**A proportional share is being expressed by writing a fixed number**, which is what the user does not
want anyone doing (2026-07-28: *"I don't want other developers to write fixed measure"*). Worse, it is
three coupled fields whose combination is folklore: get one wrong and the split silently reverts to
content-sizing, which is exactly the bug it was written to fix.

# Why it is there

`flex_grow` distributes only **positive free space**. Container content is routinely taller than a
sidebar, so there is no positive free space to distribute — measured 2026-07-28: two containers took
**1214px each inside a 600px body** and divided nothing. In CSS the answer is `flex: 1 1 0`; the base
size of 0 is what makes the whole region free space. With it: **296px each**, measured.

**`Layout` has no `flex_basis`** (confirmed — `grep flex_basis heca-grid-ui/src/style.rs` is empty),
so `height = Px(0)` is standing in for it. taffy *does* have `flex_basis` in its `Style`, so the
concept is available one layer down and simply was never surfaced.

# What to build

1. **Add `flex_basis: Option<Length>` to `Layout`** and map it in `to_taffy`
   (`heca-grid-ui/src/style.rs`). That is the missing word in the vocabulary; everything below already
   understands it.
2. **Give the library one way to say "take a share"** so no caller assembles the trio by hand — a
   builder on `LayoutExt` (`heca-grid-ui/src/builders.rs`), e.g. `share(n)`, meaning *n shares of the
   parent's main axis*, setting grow + basis 0 + min 0 + shrink internally. Then:
   - `with_share` becomes one call and stops naming a measure;
   - the SDK's `Style` trait (`heca-view/src/build.rs`) exposes the same thing, so a **described** tree
     can say it too — today it can only set `flex_grow`, which has the same trap;
   - `grow()` stays as the raw flex knob for callers who genuinely want content-based basis.
   Decide whether `grow()` should be *renamed* or documented as the low-level one, so the obvious name
   is the one that behaves as expected.
3. **Main-axis, not height.** `flex_basis` is main-axis relative like `flex_grow`, so one setter covers
   a column and a row (the same reason `ContainerContribution::grow` is not called `height_grow`). Do
   not add a per-axis variant.
4. **Sweep for the same folklore elsewhere.** `ScrollRegion::new()` already sets `min_height: 0` and
   `flex_shrink: 1` by hand with a long comment explaining why (`heca-grid-ui/src/widgets/scroll_region.rs:274`).
   Check whether that is the same idea written a second way, and whether it should go through the new
   setter.
5. **Tests must measure, not inspect flags.** A test asserting `flex_grow == 1.0` passed while the
   layout was visibly broken (2026-07-28) — the measured-height test is what caught it. Assert
   pixels: two shares of a 600px region are ~296 each, with content far taller than either.

# Acceptance

- No caller writes a fixed measure to express a proportion — not in `heca`, not in the SDK, not in a
  described tree.
- One setter, documented, with the trio behind it.
- `docs/widgets.md` says how to take a share, next to R8 (the stretch contract) in
  `docs/chrome-and-ui.md` — the two rules are read together.
- Whole workspace green, clippy 0 warnings.
