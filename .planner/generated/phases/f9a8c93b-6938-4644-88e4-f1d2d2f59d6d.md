### 📋 bd6b5935-a55b-4ad0-b26d-fcfd3985c611 — T009 — gridui-debt Dialog font-derived min-width needs Style min_width

Status: 📋 `planned`

**Rescued from the old root `HANDOFF.md` §3c (deleted 2026-07-13); do not lose this.**

A short confirm dialog ("Delete Pane?") renders **cramped** — the panel hugs its content, so a two-word title + two buttons produces a tiny box, and dialogs of different content have visibly different widths with no shared baseline.

## The gap
`Style` (`heca-grid-ui/src/style.rs`) has **no `min_width`** — only `width`/`height` (`Length::{Auto, Px}`). So `Dialog` cannot express "hug the content, but never below a sensible floor".

## Work
1. Add `min_width: Length` (and probably `min_height` for symmetry — decide) to `Style`, defaulting to `Length::Auto`, and wire it into `Style::to_taffy()` (taffy has `min_size`). Add the builder to `LayoutExt`.
2. Give `Dialog`'s panel a **font-derived** minimum — the note said **~22em** (i.e. `22 × base font`), so it scales with the theme font instead of being a magic pixel count. Verify against the real dialogs (delete-pane confirm, the rename form).
3. Tests: a `min_width` smaller than the content is a no-op; larger than the content floors the box; it scales with the base font.
4. `docs/widgets.md`: the `Style`/`LayoutExt` tables + the `Dialog` entry.

## Why it's here
`gridui-07` (crate-review debt) is the right home: it is a missing primitive in the layout style, not a feature.
