## Rules settled — do not re-litigate

- **A target names a row; the component resolves it.** The host resolves *which* row (container under
  the point + `nav_key`) and *when* to open a menu. It never learns what kind of rows exist.
- **A click is a named action, declared per item kind.** Nothing is inherited between kinds and a kind
  with no gesture declares none. A closure is reachable from one place only; an `Intent` answers the
  click, the `prefix+/` pick, a menu entry, a key and RPC.
- **An app action is not bent at a container's cursor** (user, 2026-07-30). Cursor-dependent verbs are
  the component's own (`r`, `x`, …); the app's keys keep one meaning everywhere.
- **A widget's hit area stays inside the box it reserved.** The host must never arbitrate a pixel two
  widgets claim — that couples every press path to a widget's internals. Delete the overlap instead.
- **Policy is two axes.** `ActionPolicy` = what kind of act; `Domain` = what owns the screen. An
  overlay declares only *its own coverage*; a plugin never declares policy for actions it does not own.
- **Nothing is restored when an overlay closes.** Chrome focus is not a mode and an overlay never
  takes it away.

## Traps that cost time — read before touching these areas

- **One question to a type, one answer per seating.** Anything that walks
  `ChromeHost::mounted_providers()` and *merges* results gets one answer per **placement**. Every row
  menu listed its entries twice for exactly this reason, and with one dock on screen the bug does not
  exist at all. Key by mount id, and **seat a component twice** to find the next one.
- **A rule that fires on every sync is not the rule you wrote.** `sync_focus`
  (`heca/src/app/focus.rs`) runs after *every* layout change. "The dock cursor follows the active
  pane" written there unconditionally yanked the user's cursor whenever anything changed — renaming a
  non-active pane was the report. It is `cursor_follow(prev, now)` now, guarded on the active pane
  having actually changed. Any future "X follows Y" belongs beside it, guarded the same way.
- **A `bool` passed at N call sites will be wrong at one of them.** `covers_content` was, and a
  context menu that declared `false` let `prefix+x` raise the close-pane confirm behind an open menu.
  `content_covered()` derives it (`covers_content || modal`) so no call site can re-open it.
- **`Row` and `Item` activate on mouse-down and report the press handled.** Any press-consuming widget
  fights drag detection; that is the whole of T368. If you add a draggable row, check the press order
  in `heca/src/mouse.rs` before assuming the drag will start.
- **Patch scripts: a `python` heredoc that writes file A and then fails an assert on file B leaves A
  changed and B untouched** — and an `ok` printed by an earlier command is not proof yours ran. The
  menu-coverage fix was written, never applied, and shipped to the user for testing that way. Verify
